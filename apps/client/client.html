agent-ide

Why use this over ChatGPT, Claude, T3 and the rest? Maybe you wouldn't. I do, because I like being able to change absolutely everything.

agent-ide is a minimal, stable base for building on AI. It's the chat app you know, with many threads and any model you like, plus a few things on top:

  1. Threads with many authors. You, friends, agents and bots, in one thread.
  2. Runners. Agents work on a machine and in a folder you choose.
  3. Threads that talk. An agent asks another thread, and the answer comes back once.
  4. Memory. Long threads become short lines an agent can zoom back into.
  5. Forks. Start a new thread from any message.
  6. Stays on. A restart or a crash loses nothing.

It runs on a server you own, with agents on your own machines, and nothing third-party except the model. Fork it, point your AI at it, change it.

The rest of this page walks you through it.

Hello, Agent IDE

Start it where it can stay on.

npx github:oskarrough/agent-ide

Connect another machine

So far, agents work on the machine where the server runs. Connect another, and they can work in a folder there, with that machine's tools and logins. We call it a runner. It has to reach the server: same network, or Tailscale.

Where the work happens

The agent lives on the server. Its tools and model calls run on the runner.

Agents talk to each other

An agent can ask another thread. The answer comes back once and wakes whoever asked. Each turn an agent works is one line; open it for every step. An ask reads like those steps: → and whom it went to, in the colour of their bot, then the question's first line; ← and the same name, then the answer's. A message that came in unasked is ← and who sent it. Each is one line; open it to read it whole. Everything else stays where it was said.

Want a second opinion? Have the agent ask two others, and put their answers together.

Pull the plug

Ask something slow. While its wire is green, stop the server with Ctrl-C and start it again. The server goes dashed, then green, and the answer lands, once.

This page keeps nothing itself. Close the tab, or the laptop, and nothing is lost either.

Fork

Wish you'd asked differently? Hover any message for its fork. A new thread starts from there, remembering only what came before it. The two sit side by side, linked both ways.

Bring a friend

A thread isn't yours alone. Send someone the link and they're in it, writing next to you and your agent.

There are no accounts: a name is whatever you say it is. Keep the server on a network you trust.

Memory

A thread that never has to end. Each message gets one short line, pairs of lines merge into one going up, and an agent reads those lines instead of every word. When it needs the words, it zooms back down. Click a line to do the same.

Load a thread of three people building a shed: 32 messages, where the gate code and the colour change halfway. Watch the lines get written, from the messages up. Then ask an agent what's true now.

Under it all

You ask an agent by what it is, and where:

sonnetmodel:highthinking@laptoprunner

And here's one message, start to finish:

sequenceDiagram
  participant You as You, in any client
  participant A as The agent, on the server
  participant R as runner laptop
  participant M as The model's provider
  You->>A: "fix the flaky test"
  A->>R: model request
  R->>M: with the laptop's login
  M-->>A: call bash
  A->>R: bash: pnpm test, in ~/code
  R-->>A: what it printed
  A-->>You: its answer, live as it lands

Everything is a module. Bots, memory and @mentions are on; Matrix rooms and web search you switch on in settings, beside the runners. The words, the principles and the API are in the README. The code is small enough to read in an evening.

# AGENTS.md

## Working here

- Read [FEATURE-MAP.md](FEATURE-MAP.md) first to find the file and function a task touches; update it when you add or move a file or a major function.
- Work on `main` with jj, each worker in its own jj workspace: `mkdir -p .work && jj workspace add .work/<short-name> -r main` run from `~/sites/agent-ide` (`.work/` is git-ignored), then `pnpm install --frozen-lockfile` in it. All edits, examples and scratch servers run there, never in `~/sites/agent-ide` itself or any other copy. When done: run `bun fmt`, commit everything in your workspace with `jj commit -m …`, `jj git fetch`, rebase your commit onto `main` and resolve your own conflicts, move the `main` bookmark to it (`jj bookmark set main -r <id>`), `jj git push`. If `jj git push` is refused over SSH, fetch and push over HTTPS with the GitHub CLI login, and check the push output says main moved. Then forget the workspace (`jj workspace forget <short-name>`) and delete its folder. Screenshots and scratch files go inside your own workspace, never `/tmp`: file tools reach only `~/sites/agent-ide`. Never abandon, restore or revert someone else's work (formatting it is fine); if you need lines someone else is changing, post to their thread and agree who goes first.
- While a sprint holds pushes, a worker stops before `jj git push`: commit, rebase onto `main`, move `main`, bring Oskar's checkout up to it, forget the workspace. The lead squashes and pushes at the sprint's end.
- When you mention a thread to Oskar, use its title, not its number.
- jj workspaces have no `.git`: use `jj status`, `jj file list` and `jj log -r main@origin` to inspect them.
- A long run in a workspace, like a real-model bench, can leave its working copy stale when others move `main` meanwhile; copy your changed files aside before `jj workspace update-stale`, then check `jj status` still has them.
- `~/sites/agent-ide` is Oskar's own checkout; :3000 runs from it and he may have uncommitted edits there. After pushing, bring it up to `main` without disturbing those edits: in it, `jj rebase -s default@ -o main` (rebases his in-progress working-copy commit onto the new `main`; resolve conflicts only in files you both touched, otherwise they're his to settle), then `jj workspace update-stale` if it reports the working copy is stale. Touch nothing else there, ever.
- Use agent-ide the way a person would. `node scripts/try.js &` starts a scratch server in a second with bots and director on, three scripted bots (ada, bram, cleo) that answer at once with their name, persona, how many messages they were handed and the newest, the scripted agent `echo/echo@bot` (`slow` in a message runs a 5-second tool, `post` makes it ask another thread, and `slow` carries over to the thread it asks, so `slow post` gives a live exchange to watch), and one answered thread; it prints its address, the `export AGENT_IDE_SERVER=…` for the CLI, and the `kill` that stops it. `MODULES=+web-search node scripts/try.js` turns on more modules, as +/- changes layered on top of its own list. Then each step is one command: `node cli.js post --to ada --to bram "hi"` starts a thread and prints the answers; `post --thread N "@cleo …"` writes and waits; `post --thread N --no-wait …` then `wait N` waits for the answers; `read N --after id` shows what's new; `threads` lists them. Sending to a bot by name invites it. In the browser, `agent-browser --session <yours> open <url>` with `chat` added to its query (`/?chat`, or `&chat` after `?thread=N`; without it the page opens on the walkthrough), `fill textarea "<text>"`, `press Enter`. `fill` sets text without key events, so anything that reacts to typing, like the @mention list, needs `keyboard type`; pick an option with `find role option click --name <bot>`, or `tap @ref` from `snapshot` at phone width. Read back with `node cli.js wait N`, `snapshot` (the model button's name says whom the message asks), or one `eval` of `document.querySelector('.thread').innerText`; a run's steps show once you click `li.turn:last-of-type summary`. For real data, `PORT=<free> DB_PATH=<your copy>.sqlite node server.js` on a copy of `agent-ide.sqlite`. Never touch Oskar's own server on :3000, never `pkill`/`killall` anything; stop only the pid you started (`kill $!`), and don't build proxies, harnesses or helper scripts: if agent-ide plus agent-browser can't show it, stop and ask. For what a page fetches, hears on its socket, or stalls on, open it with `--init-script <repo>/scripts/page-spy.js` (an absolute path) and read `spy` back with `eval`; `eval` takes no bare top-level `await`, so return the promise instead.
- Before backgrounding a server, `cd` into your workspace first; start it and capture `$!` in the same shell, with absolute log and pid paths.
- Test in proportion. A style, copy or layout tweak gets no browser check: trust the code, and Oskar reports what looks wrong. Look only for new or redesigned UI. agent-browser never reports a mouse, so hover rules inside `@media (hover: hover)` show only on a real one; check those in the CSS and say so. Logic runs the examples it touches. Server behaviour and contract changes get an example that fails on the old code first (say so) and the full suite. If a check fails twice, stop and report. When you had to work something out about checking that this guide should have told you, say it in one line of your report; the lead adds it here. A model check uses the scripted bot, or `gpt-6-luna:low@oskar` when it needs a real one. To measure a run, read its agent's conversation with `GET /api/conversations/:id` (the id is the agent's `conversation` in `GET /api/threads/N`): every tool call and each answer's token usage are there.
- Examples don't wait out real time: a delay, a duration or a retry count goes in as a small value (the scripted bot's `sleep 0.5`, a short setting), never a longer timeout; wait for the event, not the clock. A flaky example gets its cause fixed or is deleted, never a retry or a longer timeout.
- `pnpm install --frozen-lockfile` in a fresh checkout; leave package.json and the lockfile alone unless the task is about dependencies. After packaging changes, prove npm and npx installs; Chord's optional `ws` peer must fit the root range.

## What to build

- A change serves a promise in [apps/client/client.html](apps/client/client.html), or it needs a chat with Oskar. When an idea looks wrong, Oskar's included, argue before building.
- New features are modules, off by default.
- A thread's contract (its entries, their data, what the API returns) and how the client shows it are two decisions. A UI wish is solved in the client from existing entries; change the contract only on purpose, in its own commit, with the README and an example.
- Don't over-fix. A rare failure that would need a new store, task layer or journal stays a known gap, written on its issue.
- Hold the bar of Apple restraint and Bret Victor's directness: show the thing itself, make the invisible visible, keep people in control.
- A new panel, popover, row or button reuses its siblings' markup and styles (header, rows, buttons); nothing custom. FEATURE-MAP.md says where the popover pattern lives.
- Keep client.html and the README saying what the code does. Docs and UI copy read like a person talking.

## Words and names

- The README says what each thing is; use its words, one per concept. A thread has one agent whose model, thinking and runner change in place; only bots have names.
- A name says what it holds and stays the same in every layer, so `rg` finds the whole path (a `To` is `to`). No one-letter names, but `_` and memory's stored `l`, `i` and `n`.

## Code

- Prove logic in `examples/`, one file per idea, through the API, socket or CLI, never server internals. `examples/00-the-api.js` is the README's walkthrough: change both together. No unit or UI tests, no TypeScript, no build step, no migrations or shims.
- Durability, ordering, retries and cancellation are Pi Durable's: find its primitive before writing your own. A tool's cancellation is `execute`'s third argument's `abortSignal`; pass it through runner calls and settle locally.
- In a Pi commit, `submit(tx, ...)` comes before table writes; after the first write it can't scan entries or snapshot. A snapshot inside a commit deadlocks silently. Copy document values before they leave the commit.
- Pi forks restore `pi.agent` at the fork entry, so the creating commit applies the thread's tools and identity without replacing the inherited model, thinking or folder.
- One web client: Solid 2, no build step, in apps/client. Read `CHEATSHEET.md` and `skills/solid-2.0/SKILL.md` in node_modules/solid-js first; fix `[CODE]` console warnings with `skills/reactivity-diagnostics/SKILL.md`. In templates, wrap live values in `() =>` and give callbacks an argument. Every bare import in the import map is a root dependency. An element filled by `innerHTML` takes no component or live value after it in the same template; give that content its own template.
- A runner message's own fields never include `id` (the call's id is replaced and no reply matches), and an example needing two models uses a provider that isn't `echo`, whose models all answer as the first. An example that has its runner in its own process (`localRunner`) runs the CLI with async `execFile`, never `execFileSync`, which would stop that runner answering.
- Resolve installed packages (`import.meta.resolve`), never assume `<app>/node_modules`.
